== Solution Strategy

// The handful of fundamental decisions that shape everything else:
// technology choices, top-level decomposition, how the quality goals
// are achieved. A short summary - the detail belongs in chapters 5-9.

=== Technology

[cols="1,3", options="header"]
|===
| Area | Choice

| Backend
| Python (see <<adr-python-backend>>) with FastAPI (see
  <<adr-fastapi>>).

| Frontend
| Single-page application in React and TypeScript, talking to the
  backend over an HTTP API (see <<adr-react-frontend>>). Chat replies
  stream as Server-Sent Events; there are no WebSockets.

| AI
| Anthropic Messages API, called directly (see <<adr-anthropic>>).
  Ingestion and topic-level chats send PDF pages as documents and use
  Claude's vision capability.

| Storage
| Filesystem only. A user is a directory; course PDFs, all derived
  Markdown artifacts, and student state are files in it (see
  <<adr-no-login>>).

| Background work
| None beyond a request: the operator's command runs ingestion, and
  finalization runs as a background task of the backend process (see
  <<adr-operator-ingestion>>).

| Retrieval
| None. Every topic records its source pages, and a topic-level chat
  loads them; there is no vector store and no embedding pipeline.
|===

=== Principles

. *Markdown as the data layer.* All derived content lives in
  Markdown files the student can open in the UI. JSON holds only the
  topic list and intermediate pipeline results.
. *Originals, not transcriptions.* Nothing of the material is
  transcribed. The tutor reads the original pages, figures and
  formulas included.
. *Ingest once.* The whole material is analysed once per course, and
  tutoring sessions run on the pages of one topic.
. *Context discipline.* Sessions load only the current topic's
  artifacts and source pages - never entire courses.
. *Fail gracefully on missing materials.* The pipeline adapts to
  whatever material there is for a course.
. *Multi-tenant by design.* All data is strictly namespaced per user;
  there is no shared state between users.

=== Quality Goals

[cols="1,3", options="header"]
|===
| Quality goal | Approach

| Exam readiness
| Past exams define the topics and their priority; the tutor works on
  the original exam tasks and calibrates difficulty and working time
  against them; progress per topic and a cheatsheet written during
  the chat.

| Cost efficiency
| Ingest once in a single request, context discipline, two model
  tiers, prompt caching of the source pages in chats.

| Transparency
| Markdown as the data layer, every file readable in the UI.

| Honesty
| Gradability tiers on every task; Tier C named to the student;
  assessed and self-reported signals stored separately.

| Tenant isolation
| Per-user namespacing of files and data.

| Ease of self-hosting
| docker-compose deployment; no local models, all inference at
  Anthropic.
|===
