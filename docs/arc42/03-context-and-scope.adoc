== Context and Scope

// The system boundary: which communication partners exist, and what
// crosses the boundary. Business context first, technical context
// only where the protocol or channel matters.

The system is one self-hosted instance. Its file storage is part of
it and deployed with it; it is not a communication partner.

=== Business Context

[plantuml, target=business-context, format=svg]
....
include::diagrams/business-context.puml[]
....

[cols="1,2,2", options="header"]
|===
| Partner | Input to the system | Output from the system

| Student
| Choice of user, chat messages and answers, self-ratings for Tier B
  tasks
| Tutoring and grading in chat, all Markdown files of the course
  for reading

| Operator
| Deployment, instance configuration including the Anthropic API
  key, users, course PDFs and `notes.md` for each student
| A running instance

| Anthropic API
| Topics with their source pages, tutor replies and grading, updated
  progress
| PDF documents, topics, artifacts, and prompts -
  authenticated with the instance's API key
|===

The student's course material leaves the instance only towards the
Anthropic API.

=== Technical Context

[cols="1,1,3", options="header"]
|===
| Partner | Channel | Notes

| Student
| Browser, HTTP
| Web UI over a JSON HTTP API. A chat message is a `POST` carrying
  the chat's transcript, whose response streams the reply and its tool events as Server-Sent
  Events. Open chats are loaded and ended with their own requests.

| Operator
| Docker host
| docker-compose, `.env`, and the user and course commands of
  the application image (chapter 8). Course material is read from the
  directory `courses/` next to the compose file.

| Anthropic API
| HTTPS
| Outbound only. Requests carry PDFs as document input. Every request
  carries the instance's API key.
|===
