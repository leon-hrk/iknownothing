The system runs on one host as a docker-compose setup of one
service and the directories `data/` and `courses/`. It is set up for use on the host itself: `backend`
publishes one port, bound to `localhost`, and speaks plain HTTP.

[cols="1,3", options="header"]
|===
| Service | Content

| `backend`
| The application image running the FastAPI application. Serves the
  HTTP API and the built frontend as static files. The operator runs
  the user and course commands in it with `docker compose exec`.

| Directory `data/`
| The filesystem of <<_persistence,Persistence>>, next to the compose
  file and mounted into `backend`, which runs as the operator's user
  ID so that the operator owns the files.

| Directory `courses/`
| The course material the operator adds courses from, next to the
  compose file and mounted read-only into `backend` at `/courses`.
|===

Configuration is passed as environment variables from a `.env` file
next to the compose file: the Anthropic API key, the model of each
<<_ai_requests,model tier>>, the port, and the user ID that owns
`data/`. The
repository contains only `.env.example`. How the key and the file are
protected is described in <<_secrets,chapter 8>>.

The application does not authenticate its users (chapter 11). An
operator who serves a group of users over the network binds the port
to the network and puts a TLS-terminating reverse proxy in front of
`backend` that authenticates every request, e.g. with HTTP basic
auth; the proxy is not part of the setup.

The deployment is bound to one host: `backend` keeps its files in
the `data/` directory. All inference runs at Anthropic, so the host
itself does little more than wait on the network. The number of users
is bounded by the rate limit and budget of the one API key they share
(chapter 11), not by the host.
