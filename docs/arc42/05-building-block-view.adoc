|===
| Building block | Responsibility

| Frontend
| React single-page application in the browser: user choice, course
  tree, and a workspace of tabs and split groups for chats, Markdown
  files, and PDFs. Talks to the backend over the HTTP API only.

| Backend
| FastAPI application serving the HTTP API. Handles requests, streams
  chat replies as Server-Sent Events, and stores open chats. Its
  image also holds the operator's user and
  course commands (see <<adr-operator-ingestion>>).

| Filesystem
| Users and their course content under `data/<user>/`, laid out as described in
  <<_persistence,Persistence>>.
|===

The frontend is not decomposed further.

=== Level 2: Backend

The HTTP API and the operator's commands share one set of modules;
Ingestion runs only in a command.

[plantuml, target=building-blocks-level2, format=svg]
....
include::diagrams/building-blocks-level2.puml[]
....

[cols="1,3,2", options="header"]
|===
| Module | Responsibility | Owns

| Accounts
| The list of users, the user a request is served for (chapter 8),
  and the user commands the operator runs from the command line.
| The user directories `data/<user>/`

| Courses
| Listing a user's courses with their status - ready or not
  ingested, read from the files - and reading course files through
  the Course Store. The operator's course commands: adding a course
  for a user from a directory of PDFs and `notes.md` and ingesting it,
  adding the new PDFs of that directory to an ingested course and
  ingesting them, resuming a failed ingestion, and removing a
  course.
| -

| Course Store
| The only access path to `data/<user>/<course>/`. Knows the storage
  layout and resolves every path within the requesting user's
  directory.
| The filesystem

| Ingestion
| The ingestion pipeline: conversion, topic extraction, topic files,
  topic list, and reference solutions. Splits conversions into blocks
  and assembles a topic's passages with their figures, for itself and
  the Tutor. Runs in the operator's command; each step writes its result
  through the Course Store before the next one starts and is printed
  as it starts (see <<runtime-ingestion>>).
| -

| Tutor
| Course-level and topic-level chats: assembles each chat's context
  from the Course Store, a topic's tasks included, streams replies as Server-Sent Events,
  executes the chat tools - recording a completed step in the topic's
  `progress.json` - and stores the open chat after each reply.
| -

| AI Client
| The only caller of the Anthropic API. Loads prompts, sends each
  request with the instance's API key on the model of its tier
  (chapter 8), records its token usage, and streams responses back.
  With `IKN_MOCK_USER=1`, the API adds the user `mock`, whose
  courses are sample data bundled with the mock client. A mock client
  answers its chats: a message `/<name>` gets the sample reply of
  that name, `/tools` a reply that poses a task in a tool call, any
  other message the list of commands. Each reply starts with a
  thinking summary. Other requests fail. Its chats open as a sample
  chat that sends each command once, and nothing of them is stored. All other users are unaffected.
| Prompts

| OCR Client
| The only caller of the Mistral OCR API. Sends a PDF with the
  instance's Mistral API key, retries rate-limited and failed
  requests, returns the Markdown and the figures of every page, and
  logs the pages processed.
| -
|===

==== Prompts

Every prompt is a Markdown file in the backend source tree, one per
task (topic extraction, task assignment, task grouping, solution
writing, planning, tutoring). The AI Client loads them by name; other
modules never build prompt text inline.
