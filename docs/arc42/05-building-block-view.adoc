[cols="1,3", options="header"]
|===
| Building block | Responsibility

| Frontend
| React single-page application in the browser: user choice, course
  tree, chat, Markdown viewer. Talks to the backend over the HTTP API
  only.

| Backend
| FastAPI application serving the HTTP API. Handles requests, streams
  chat replies as Server-Sent Events, and finalizes topic-level chats
  in the background. Its image also holds the operator's user and
  course commands (see <<adr-operator-ingestion>>).

| Filesystem
| Users and their course content under `data/<user>/`, laid out as described in
  <<_persistence,Persistence>>.
|===

The frontend is not decomposed further.

=== Level 2: Backend

The HTTP API and the operator's commands share one set of modules;
Ingestion runs only in a command.

[plantuml, target=building-blocks-level2, format=svg]
....
include::diagrams/building-blocks-level2.puml[]
....

[cols="1,3,2", options="header"]
|===
| Module | Responsibility | Owns

| Accounts
| The list of users, the user a request is served for (chapter 8),
  and the user commands the operator runs from the command line.
| The user directories `data/<user>/`

| Courses
| Listing a user's courses with their status - ready or not
  ingested, read from the files - and reading course files through
  the Course Store. The operator's course commands: adding a course
  for a user from a directory of PDFs and `notes.md` and ingesting it,
  copying an ingested course from another user, resuming a failed
  ingestion, and removing a course.
| -

| Course Store
| The only access path to `data/<user>/<course>/`. Knows the storage
  layout, resolves every path within the requesting user's directory,
  and cuts source pages out of the PDFs.
| The filesystem

| Ingestion
| The ingestion pipeline: topic extraction, topic files, and topic
  list. Runs in the operator's command; each step writes its result
  through the Course Store before the next one starts and is printed
  as it starts (see <<runtime-ingestion>>).
| -

| Tutor
| Course-level and topic-level chats: assembles each chat's context
  from the Course Store, a topic's source pages included, streams replies as Server-Sent Events,
  executes the chat tools, and finalizes
  topic-level chats by updating their `progress.md`, in a background
  task after the response.
| -

| AI Client
| The only caller of the Anthropic API. Loads prompts, sends each
  request with the instance's API key on the model of its tier
  (chapter 8), records its token usage, and streams responses back.
| Prompts
|===

==== Prompts

Every prompt is a Markdown file in the backend source tree, one per
task (topic extraction, planning, tutoring, finalization). The AI Client loads them by name; other modules never build
prompt text inline.
