== Risks and Technical Debt

// Known risks and accumulated debt, ordered by priority, each with
// what would mitigate it. This chapter is for problems we already
// carry, not decisions we have not made yet.

=== Risks

[cols="1,2,2", options="header"]
|===
| Risk | Impact | Mitigation

| No authentication
| Users choose themselves without login (<<adr-no-login>>). Anyone
  who reaches the application can use and read every user's courses
  and spend the API key.
| `backend` is bound to `localhost`. For network access, a reverse
  proxy that authenticates every request (chapter 7). Login
  (chapter 1, out of scope) removes the risk.

| Topics shaped by the order of past exams
| Topic extraction reads the past exams one after another
  (<<adr-units>>). The first exam sets the granularity of the topics;
  a later one can add and describe topics but not merge or split
  them. Exercise content no exam asks for is grouped into topics only
  at the end, from the tasks no topic took.
| Topics are defined by skill, not by exam. Checked by hand on the
  reference courses (Q1). Merge and split operations in the reply
  remove the risk.

| OCR errors in the converted sources
| The conversion (<<adr-mistral-ocr>>) is not reviewed. A misread
  formula or a figure the OCR does not cut out is wrong or missing in
  the Markdown.
| The student sees the converted sources in the UI. Checked by hand
  against the PDFs on the reference courses.

| Task cut too tight
| A block range misses data, a figure, or part of the solution the
  task needs (<<adr-task-blocks>>). The tutor then works without it.
| The prompt asks for the introduction and referenced data of every
  subtask. Checked by hand on the reference courses (Q2).

| Missing lecture content
| The lecture is not ingested (<<adr-no-lecture>>). The tutor teaches
  definitions, formulas, and notation in its own words, which can
  differ from the lecture's.
| The tutor marks what it explains in its own words. Lecture material
  through retrieval (chapter 1, out of scope) removes the risk.

| Misclassified gradability tier
| Tiers are assigned by the model without review. A Tier C task
  classified as Tier B is posed and cannot be answered; a Tier A task
  classified as Tier B loses a graded signal.
| Checked by hand on the reference courses (Q8).

| Wrong topics
| Topics are built without review. A missing, split, or misnamed
  topic propagates into progress, and fixing it means re-ingesting
  the course. Material no topic takes up is visible nowhere.
| `notes.md` feeds topic extraction. Topic review (chapter 1, out of
  scope) removes the risk.

| Shared rate limit and budget
| All users run on one API key. Parallel ingestions exhaust its rate
  limit and slow down every chat; one user's heavy use spends the
  budget of all.
| Ingestions are started by the operator, one per command; a spend
  limit on the key caps the cost. Per-user keys (chapter 1, out of scope) remove
  the risk.

| Finalization lost on restart
| The chat is removed when its session ends, before finalization
  runs. A finalization running when the backend stops
  (<<adr-operator-ingestion>>) loses its progress update.
| Accepted for v0. The cheatsheet is unaffected; it is updated during
  the chat.

| Sessions left open
| Progress is only updated when the student ends a session. A session
  never ended leaves `progress.md` behind, and its transcript grows
  with every message, and with it the input tokens of every request.
| Accepted for v0. The token usage of the open session is shown next
  to *End session*.
|===
